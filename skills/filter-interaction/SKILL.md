# 列表筛选交互实现规范（今日热搜项目）

## 什么时候用我

- 给现有列表加筛选框、过滤、搜索功能
- 修改或排查已有筛选逻辑
- 审查一个筛选功能是否合格（验收）

## 实现步骤（按序执行，逐条打勾）

1. **定数据源**：筛选只对内存里的已有数据做（`boardData` 等），**不新增网络请求**。
2. **三种情况逐一落实**（这是本 Skill 的核心）：
   - **有结果**：渲染过滤后的列表，条目数与关键词一致
   - **无结果**：显示空态文案「没有匹配"xxx"的条目」+「清空筛选」出口按钮——**不是报错态**，不弹「获取失败」
   - **清空恢复**：清空输入后，列表必须完整恢复到筛选前（条目数回到原值，不能有残留过滤）
3. **反馈设计**：筛选生效要有可感知反馈——优先「状态翻转」（如实时结果计数「3/6 条」），其次动效；纯输入无反馈 = 不合格。
4. **XSS 防护**：用户输入的筛选词如果要回显到页面（空态文案里），必须经过 `escapeHtml()`。
5. **样式规范**：新 UI 的颜色一律取 `:root` 变量（`--text-sub` / `--text-hint` 等），间距只用 4/8/12/16 档位。
6. **输入细节**：`input` 事件实时过滤；空字符串等同「清空」，走恢复逻辑；筛选状态在刷新数据后要考虑是否保留（默认不保留，简单优先）。
7. **验证**：三种情况各写一条自动化断言 + 移动端 375px 无横向溢出 + 已有交互回归不破坏。

## 坑（全部来自本项目实战，别再踩）

| 坑 | 出处 | 正确做法 |
|---|---|---|
| 空结果被当成报错 throw | Day 8（知乎空数组被误判「获取失败」） | 空是状态，不是异常 |
| 断言只查 `classList`，样式实际没生效 | Day 13（`.hidden` 无通用规则，class 加了但没隐藏） | 断言查 `getComputedStyle().display` |
| 无头浏览器合成事件不触发 `:hover` | Day 9/11 假阴性 | hover 类验证改为查样式表规则是否存在 |
| flex 子项被长标题撑出横向滚动 | Day 7 | 容器/子项记得 `min-width: 0` |
| Edge 无头 `--window-size` 视口漂移 | Day 9 | 窄屏验证用 iframe 固定宽度再截外层 |
| 动效中间帧被截进交付图 | Day 11 | 截图前临时 `animation: none` 取终态 |
| `flex-basis: 100%` 在 column 布局指「高度」而非「宽度」，配合 wrap 会把后续子项挤到新列、横向溢出 | Day 12（筛选栏在移动端溢出 324px） | 想独占一行只在 row 布局用 flex-basis:100%；column 布局的媒体查询里重置为 `auto`，宽度交给 stretch |
